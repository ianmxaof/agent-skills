# PowerCore UX prefs

Living interaction doctrine for PowerCore UIs. Visual tokens stay in
`powercore-chrome.*`; chat schema in `chat_contract/`. This skill owns **feel**:
scroll ownership, focus, keys, rail behavior — and keeps the index dense.

## Canonical index

`C:\Powercore-repo-main\powercore-ops\design\powercore-ux.preferences.md`

Always-on tip: `.cursor/rules/powercore-ux-prefs.mdc` (points here).

## When to invoke

- Building or changing any PowerCore UI (Tk, web, Hub)
- Operator UX complaint / “always should…” preference
- `/ux-prefs`, `/powercore-ux`, “apply chrome prefs”, “capture this UX rule”
- **Seed from threads:** “seed UX prefs”, “mine chatlogs for UX”, `/ux-prefs seed`
- Before claiming a UI fix done (especially scroll/focus/sidebar)

**Skip:** pure backend, docs-only, non-PowerCore repos with no shared chrome.

## Modes

### APPLY (default on UI work)

1. Read `powercore-ux.preferences.md` (and linked chrome / `ui_defaults` as needed).
2. Map the change to matching `PX-###` rows.
3. Implement so prefs hold — not just the local symptom.
4. If a sibling surface is named under **Surfaces** and in scope, twin it or note why not.
5. Summary: list `PX-###` applied (one line).

### CAPTURE (after operator UX correction)

1. Fix the surface.
2. Open the index. Densify an existing `PX-###` if same idea; else append via the
   template in that file (`locked` / `preferred` / `fix-once` + evidence date + path).
3. If the preference belongs in `chat_contract/ui_defaults.md` (Enter-to-send,
   rail chrome), update that too — keep one sentence there, detail here.
4. Tell the operator: `Captured PX-###` (title only).

### SEED (from Cursor agent-transcript archive)

Mines **user** turns in `%USERPROFILE%\.cursor\projects\*\agent-transcripts\**\*.jsonl`
(same store `/thread-digest` uses). Composer-only chats that never became Agent
transcripts are **not** in this archive.

```powershell
cd C:\Powercore-repo-main\agent-skills
# Dry-run → candidates markdown (safe default)
py -3.13 -m tools.ux_prefs seed --all-projects --plain
# Or PowerCore project slugs only (omit --all-projects)
py -3.13 -m tools.ux_prefs seed --plain
# After review: append top hits as ``seeded`` PX rows
py -3.13 -m tools.ux_prefs seed --all-projects --apply --max-apply 15 --plain
```

Outputs: `powercore-ops/design/powercore-ux.preferences.seed-candidates.md`

Agent procedure for SEED:

1. Run dry-run first; show operator the candidate count + top buckets.
2. Do **not** `--apply` unless they ask to merge / “seed into the index”.
3. After apply: skim new `seeded` rows; densify duplicates into existing `PX-###`;
   promote confirmed ones to `preferred` / `locked`.
4. Cite transcript id in Evidence (already written by the tool).

### AUDIT (optional)

On a UI pass or when asked: scan touched UI files against `PX-001`… and report
gaps as `missed` / `covered` / `blocked` (max 5). Do not expand scope without a pick.

## Self-improve loop

```
operator corrects feel → code fix → CAPTURE
OR archive mine → SEED candidates → review → apply/promote
→ later UI work → APPLY loads denser index
```

Skill body changes that alter procedure: snapshot via

```powershell
cd C:\Powercore-repo-main\agent-skills
py -3.13 -m tools.skill_gap.skill_versions snapshot --skill powercore-ux-prefs --note "…"
```

Preference **data** lives in `powercore-ops/design/` (product truth), not under
`evals/versions/`.
