# PowerCore CC↔CC Relay (v1.0)

Changelog: v1.0 — Cursor-dark stand-in for Cursor↔Claude paste bridge; Planner/Grinder roles; fence labels; disk reports unchanged.

## Purpose

- Keep **Cursor-quality** phase gates when Cursor Pro usage is exhausted.
- Two Claude Code sessions (or two CC windows) play **Planner** (judgment/ACK) and **Grinder** (Lane C execute).
- Operator still **blind-pastes** fences — product is the fence, not prose between hops.
- Disk `tbcc/docs/handoffs/*_report.md` (+ forward directive) remains source of truth.

This does **not** replace Cursor↔CC when Cursor has quota — use `cc-report` + `tbcc-cc-run` then. This skill is the **failover pair protocol**.

## Roles

| Role | Session | Does | Does not |
|------|---------|------|----------|
| **Planner** | CC #1 (judgment) | Read reverse report + git; emit ACK/fix/wait fence; pack Prior state; unlock doctrine only when operator said so in chat | Implement Phase N+1; push; Start bots |
| **Grinder** | CC #2 (execute) | `/cc-run` style: one phase only; write `*_report.md`; STOP with planner-facing fence | Re-author Goal from vibes; skip reverse report; start next phase without ACK |

Operator may be the paste courier only (no third brain required).

## Fence labels (locked)

| Direction | First line of fence |
|-----------|---------------------|
| Grinder → Planner | `PASTE INTO CC-PLANNER` |
| Planner → Grinder | `PASTE INTO CC-GRINDER` |

**Aliases (accept, then normalize in your reply):**
- `PASTE INTO CURSOR` from Grinder → treat as `PASTE INTO CC-PLANNER` when this skill is active
- `PASTE INTO CLAUDE CODE` from Planner → treat as `PASTE INTO CC-GRINDER`

Do not invent a third label mid-thread.

## When to invoke

- Trigger phrases: `/cc-cc`, `/cc-pair`, `/cc-cc-relay`, `CC to CC`, `two Claude sessions`, `Cursor usage gone`, `no Cursor`, `Planner/Grinder`, `handoff between Claude Codes`
- Situational: operator says Cursor is dry but wants the same ACK quality; multiphase grind must continue
- **Skip:** Cursor has usable quota → use normal `cc-report` / `tbcc-cc-run`. Single CC session that both plans and grinds without a second window → still write disk reports, but this skill’s dual-fence is optional. Pure operator Q&A.

## Execution Profile

- Freedom: **low** on fence shape; **medium** on Planner verdict text
- Mode: Agent (Planner reviews; Grinder implements)
- Parallelism: none across phases; two sessions are sequential hops via paste

## Harness attach

| Surface | Value |
|---------|-------|
| **MCP** | none required |
| **Hooks** | endgates on substantive Planner turns; silent-fail when Grinder touches Beat/deploy |
| **Memory** | disk: forward `YYYY-MM-DD_<topic>.md` + `*_report.md`; chat fences are transport only |
| **Compose** | Grinder ← `tbcc-cc-run` habits; Planner ← `cc-report` habits; forward pack ← `directive-generator` / `handoff-claude-code` |

## Behavioral rules

- Reason by: **file + git**; never “as we discussed in the other terminal” without a path
- Planner falsifies Grinder claims (tests, HEAD, artifact paths) — does not defend them
- Grinder honors Planner fence `Do:` / `Do not:` over chat vibes
- Judgment ceiling: Grinder **MUST NOT** on pricing / store activate / new doctrine unless Planner fence explicitly unlocks (operator-backed)
- Avoid: both sessions implementing; skipping reverse report; overwriting an active unrelated `CURRENT_DIRECTIVE.md` without guard
- Prioritize: one phase → report → STOP → paste → ACK → next

## Output contract

### Grinder STOP (after each phase)

```text
PASTE INTO CC-PLANNER
/cc-cc-report
Report: tbcc/docs/handoffs/<stem>_report.md
Status: Phase N complete | blocked
HEAD: <hash or uncommitted>
Do: review + ACK (paste fence back to Grinder)
Do not: assume Phase N+1 started
```

### Planner ACK (after reading report)

```text
PASTE INTO CC-GRINDER
Verdict: ACK | fix | wait
Report: tbcc/docs/handoffs/<stem>_report.md
Do: <exact next — e.g. Phase N+1 only | amend report | stop>
Do not: push; start bots; touch .env; Phase N+2 unless listed
```

Optional one plain line above the fence for the human courier.

### Self-correct

1. Draft fence.
2. Check: first line exact; Verdict/Report/Do/Do not present (Planner) or Report/Status/HEAD/Do/Do not (Grinder); no Phase N+1 started without ACK.
3. Revise once if any check fails.

## Procedure

### Tickable — Planner

```
- [ ] 1. Locate *_report.md (path in paste or newest matching stem)
- [ ] 2. Read report; git log / status / show --stat vs claimed HEAD
- [ ] 3. Verdict ACK | fix | wait
- [ ] 4. Emit PASTE INTO CC-GRINDER fence only (no implement)
- [ ] 5. Stop
```

### Tickable — Grinder

```
- [ ] 1. If paste is PASTE INTO CC-GRINDER (or CLAUDE CODE alias), parse Verdict/Do/Do not first
- [ ] 2. Resolve forward path (CURRENT_DIRECTIVE guard: standalone file if pointer busy)
- [ ] 3. Execute one phase only
- [ ] 4. Append *_report.md
- [ ] 5. STOP with PASTE INTO CC-PLANNER
```

## Context parity (Planner packs like Cursor)

When starting a new CC↔CC job or when Grinder would otherwise lack Cursor thread memory, Planner (or operator) ensures the forward file has:

- Goal / Scope / Out of scope
- Prior state with **paths** (not chat-only)
- Issue cards + Verification commands
- Phases + Working agreement (reverse report + STOP)
- Judgment unlocks stated explicitly

Cold Grinder reads **disk**, not the Planner’s chat history.

## Exit conditions

- Do not auto-continue phases in the same session that just STOPped unless the operator’s paste is an ACK naming that phase
